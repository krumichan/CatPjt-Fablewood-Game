# 층간 논리 경로 기초 · 2026-10-26 / 階間の論理経路基盤

## 한국어

이번 단계는 계단·경사로의 연결 관계를 정의하고, 현재 층에서 목적지 층으로 갈 때 이용할 다음 통로 진입점을 조회하는 기초 모듈이다. 기준 소스는 Game `556b42a7fef7ec937b36f701e931ca3e2a1a79c5`와 Backend `b0e4cee15450db61ba48a5a368f66cef7b4d3de1`이다. 기존 파티 준비 취소 검증본과는 별도 작업본에서 개발한다.

### 연결 정의와 호환성

`FFableTownConnectorDefinition`의 `FromFloorId`와 `ToFloorId`는 점 목록의 첫점과 끝점이 속하는 층이다. `bBidirectional=false`이면 첫점에서 끝점으로만 경로를 조회한다. 두 층 ID를 모두 생략한 기존 통로는 위치 조회용으로 유지하며, 층간 경로에 임의로 연결하지 않는다. 하나만 지정한 경우, 존재하지 않거나 같은 층을 연결한 경우, 첫점·끝점이 지정한 층 밖인 경우는 정의 검증에서 거절한다. 기존 좌표·반경·중복 ID·유한값 검사를 유지한다.

### 경로 조회

경로 계산은 명시된 연결 통로와 같은 층의 진입점 사이 거리를 사용한다. 통로의 전체 꺾인 선 길이와 현재 위치·목적지까지의 거리를 포함해 경로를 선택한다. 양방향 여부를 따르며, 같은 비용의 경로는 입력 배열 순서가 달라도 동일하게 선택한다. 계산량을 제한하고 잘못된 입력·도달 불가에서는 이전 경로나 일부 결과를 반환하지 않는다.

Unreal 어댑터는 현재 마을·카탈로그 버전·준비 상태·실제 층 정의와 목적지 앵커를 확인한다. 카탈로그의 월드 변환을 적용한 좌표를 핵심 계산에 전달하므로 회전·이동·스케일을 거리 계산에 반영한다. 같은 층의 목적지는 직접 반환하고, 다른 층은 다음 통로의 현재 층 진입점을 반환한다. 첫 단계에서 현재 위치가 층 밖의 연결 회랑 안이면 `ConnectorUnavailable`을 반환한다. 잘못된 위치·다른 마을·오래된 버전·없는 목적지·미준비 지형·연결 없는 층은 사용할 수 없는 상태로 돌려준다.

### 게임 판정과 화면의 경계

이 결과는 논리적 안내 후보이며 장애물 없는 보행 경로나 NavMesh 검증 결과가 아니다. 층 내부의 두 점 사이 선분이 실제로 걸을 수 있는지, 계단·경사로가 실제 충돌·바닥을 가지는지는 맵 채택 시 따로 검증해야 한다. 자동 이동·순간이동·로드·저장·원격 서비스 이용·파티 입장을 수행하거나 허가하지 않는다.

이번 단계에서는 HUD·스토리·기존 `FableTownNavigation`의 표시 동작을 바꾸지 않는다. 기존 같은 층 안내를 보존하고, 새로운 경로 API를 화면에 연결하는 작업과 통로 내부의 연속 안내는 후속 단계로 둔다. 네 후보 마을의 좌표·에셋·`geometryReady=false` 상태도 유지한다. 연결 메타데이터를 실제로 채택할 때는 카탈로그 버전과 실제 맵 검증을 함께 갱신한다.

### 검증과 소스 관리

Unreal에 의존하지 않는 경로 핵심 코드 자체를 로컬 C++ 실행 검사에서 사용한다. 이 검사는 Unreal 어댑터·UHT·Native 검사·맵 로드·두 클라이언트 플레이의 통과를 의미하지 않는다. 별도 Native fixture는 연결 정의, 회전 좌표계, 일방통행, 도달 불가, 같은 층, 미준비 지형과 실패 시 출력 초기화를 다룬다. 실제 실행 결과와 미실행 범위는 아래 완료 기록에 구분해 남긴다.

유지할 제품 소스·테스트 코드·실행 도구·이 문서만 Git 대상으로 삼는다. 로컬 검사 실행 파일·오브젝트·로그·JSON 결과의 기본 위치는 `Saved/`이며 배포 소스에서 제외한다. Unreal 빌드와 실제 플레이 검증 전에는 이 작업본을 검증 완료로 표시하거나 Git 게시를 위탁하지 않는다.

## 日本語

今回の段階は階段・スロープの接続関係を定義し、現在の階から目的階へ向かう次の通路入口を照会する基盤である。基準ソースはGame `556b42a7fef7ec937b36f701e931ca3e2a1a79c5`とBackend `b0e4cee15450db61ba48a5a368f66cef7b4d3de1`である。既存のパーティー準備取消検証とは別の作業コピーで開発する。

### 接続定義と互換性

`FFableTownConnectorDefinition`の`FromFloorId`と`ToFloorId`は点列の先頭と末尾が属する階である。`bBidirectional=false`では先頭から末尾への方向だけを照会する。両階IDのない既存通路は位置照会用として維持し、階間経路へ推測で接続しない。片方だけの指定、存在しない階や同じ階への接続、指定階の外にある始点・終点は定義検証で拒否する。従来の座標・半径・重複ID・有限値検査も維持する。

### 経路照会

経路計算には明示された通路と、同じ階の入口間の距離を使う。通路の折れ線全体と現在地・目的地までの距離を含めて選択する。方向を守り、同じ費用の経路は入力配列の順序を変えても同じ結果を選ぶ。計算量を制限し、不正な入力や到達不能では以前の経路や部分結果を返さない。

Unrealアダプターは現在の村・カタログ版・準備状態・階定義・目的アンカーを確認する。カタログのワールド変換を適用した座標をコアへ渡し、回転・移動・スケールを距離に反映する。同じ階は直接の目的地を、別の階は現在の階にある次の通路入口を返す。第1段階では階の外の接続回廊内を現在地とする照会に`ConnectorUnavailable`を返す。不正な位置・別の村・古い版・欠落した目的地・未準備地形・接続のない階は利用不可とする。

### ゲーム判定と画面の境界

結果は論理的な案内候補であり、障害物のない歩行路やNavMesh検証の証明ではない。同じ階の二点間を実際に歩けるか、階段・スロープに衝突と床があるかはマップ採用時に別途確認する。自動移動・瞬間移動・ロード・保存・遠隔サービス利用・パーティー入場を実行・許可しない。

今回はHUD・物語・既存`FableTownNavigation`の表示動作を変更しない。従来の同じ階の案内を維持し、新APIの画面接続と通路内の連続案内は後続段階とする。四候補村の座標・アセット・`geometryReady=false`も維持する。接続メタデータを採用するときはカタログ版と実マップ検証を共に更新する。

### 検証とソース管理

Unrealに依存しない経路コアそのものをローカルC++実行検査に使う。この検査はUnrealアダプター・UHT・Native検査・マップロード・二クライアントプレイの成功を意味しない。別のNative fixtureでは接続定義、回転座標、一方通行、到達不能、同じ階、未準備地形、失敗時の出力初期化を扱う。実行結果と未実行範囲は以下の完了記録で区別する。

維持する製品ソース・テストコード・実行ツール・本文書だけをGit対象とする。ローカル検査の実行ファイル・オブジェクト・ログ・JSON結果の既定保存先は`Saved/`であり、配布ソースから除外する。Unrealビルドと実プレイ検証の前に、この作業コピーを検証完了と表示したりGit公開を委託したりしない。
