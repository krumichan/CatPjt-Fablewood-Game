## 전용 서버·중앙 저장과 소스 재현 (2026-10-23)

Unreal Editor 전용 서버 1개와 Windows 패키지 클라이언트 2개가 로컬 .NET API·PostgreSQL 중앙 저장에 연결되는 실제 흐름을 통과했습니다. 클라이언트는 DX11을 사용했고, 서버에는 로컬 플레이어가 없습니다. 아래 협동·특성 단계 기록은 이전 listen-server 방식의 결과로 보존합니다.

기존 로컬 `.sav`는 자동 업로드하거나 삭제하지 않습니다. 중앙 저장은 별도의 새 계정으로 시작하며, 예전 개인 진행과 테스트 원본은 유지합니다. API와 DB는 기본적으로 이 PC의 loopback에만 열립니다. 인터넷 공개 서버나 외부 인증 서비스 배포를 완료했다는 의미가 아닙니다.

### 이번 단계 검증 기록

검증 범위는 한 PC의 loopback에서 실행한 전용 서버 1개와 클라이언트 2개입니다. 물리적으로 분리된 PC, WAN, 인터넷 공개 서비스, 지연·패킷 손실 조건은 이번 결과에 포함되지 않습니다. 독립 최적화 서버 실행 파일은 아래 제한과 같이 별도 Unreal 소스 엔진 빌드가 필요합니다.

### 로컬 API와 DB 준비

Windows PowerShell 7.4 이상(`pwsh`), .NET 10 SDK, 실행 중인 Docker Engine이 필요합니다. 루트 `global.json`은 SDK 10.0.401을 기준으로 같은 feature band의 최신 patch만 허용하며 preview SDK는 사용하지 않습니다. 아래 명령은 `Fablewood.uproject`가 있는 프로젝트 루트에서 실행합니다. 먼저 저장소의 NuGet lock과 일치하도록 복원한 뒤 API를 빌드합니다. 실행기는 자동으로 소스를 빌드하지 않습니다.

```powershell
dotnet restore .\Backend\Fablewood.Backend\Fablewood.Backend.csproj --locked-mode
dotnet build .\Backend\Fablewood.Backend\Fablewood.Backend.csproj -c Release --no-restore
pwsh -NoProfile -File .\Tools\Start-Backend.ps1
```

`Start-Backend.cmd`도 같은 실행기를 호출합니다. 기본 DB는 `fablewood`, 컨테이너는 `fablewood-postgres`, named volume은 `fablewood-postgres-data`, DB 주소는 `127.0.0.1:55438`, API 주소는 `http://127.0.0.1:5281`입니다. PostgreSQL 이미지는 `postgres:18-alpine@sha256:898c60cb390d1085bc97bdd6a1ae968757421df394b071848b52b1c09c89d6a5`로 고정했으며, 18 계열의 데이터 볼륨 위치 `/var/lib/postgresql`을 사용합니다. 새로 생성하는 컨테이너도 이 digest를 사용해 같은 이미지 내용을 재현합니다. 기존 소유 컨테이너는 자동 교체하지 않습니다. [공식 PostgreSQL 이미지 설명](https://github.com/docker-library/docs/blob/master/postgres/README.md#pgdata)

실행기는 기존 컨테이너·볼륨의 소유 라벨과 loopback 포트를 확인한 뒤 DB를 준비하고, API의 `--migrate`를 명시적으로 실행합니다. 스키마 준비와 DB 연결을 확인하는 `/health`가 HTTP 200 및 `status: ok`를 반환해야 시작 완료로 보고합니다. API 환경 변수 `FABLE_DB_CONNECTION`, `FABLE_DB_SCHEMA`, `FABLE_SERVER_KEY_FILE`, `ASPNETCORE_URLS`는 `Start-Process -Environment`로 자식 프로세스에만 전달합니다. 사용자나 시스템의 전역 환경은 바꾸지 않습니다.

최초 실행 때 강한 무작위 DB 암호와 서버 키를 생성하고 `Saved/Backend/`에만 보관합니다. `backend-credentials.json`은 DB 설정, `server-key.txt`는 API 키 원본, `server.json`은 Unreal 서버용 연결 정보, `.env.local`은 Docker 전용 DB 설정입니다. 실제 값은 출력하지 않으며 `.env.example`에는 사용 불가능한 자리표시자만 있습니다. 이 폴더는 Git과 소스 manifest에서 제외합니다. NTFS에서는 폴더 접근을 현재 사용자·SYSTEM·관리자로 제한하지만, 현재 외장 exFAT에서는 사용자별 ACL이나 파일 암호화를 보장하지 않습니다. 키 파일과 DB 암호가 든 폴더를 공유하거나 공개 저장소에 올리지 마세요.

API만 다시 시작하려면 `pwsh -NoProfile -File .\Tools\Start-Backend.ps1 -Restart`를 사용합니다. 저장된 프로젝트·실행 파일·PID·프로세스 시작 시각이 일치하는 API만 종료합니다. DB 컨테이너와 볼륨을 삭제하거나 기존 다른 서비스의 컨테이너를 중지하지 않습니다. 기존 볼륨이 있는데 암호 파일을 잃었다면 새 암호로 덮지 않고 복원을 요구합니다. 실행 상태와 PID는 `Saved/Backend/backend-state.json`, 단계별 로그는 그 아래 고유 실행 폴더에 남습니다. 상태 JSON에는 암호나 서버 키가 들어가지 않습니다.

### Unreal 전용 서버 확인

위 통과 기록의 구성은 `UnrealEditor-Cmd.exe -server`로 동작하는 실제 `NM_DedicatedServer` 1개와 별도 Windows 패키지 클라이언트 2개입니다. 서버에는 다음 연결 파일 인자를 전달합니다.

```text
-FableBackendConfig="D:\GameProjects\Fablewood\Saved\Backend\server.json"
```

`Source/FablewoodServer.Target.cs`와 `Source/FablewoodClient.Target.cs`는 향후 별도 Target 빌드를 위해 준비한 파일입니다. 최적화된 독립 `FablewoodServer.exe`에는 Server Target을 지원하는 Unreal 소스 엔진 빌드가 필요하며 아직 빌드·검증하지 않았습니다. Launcher 엔진으로 만든 일반 Game Target `Fablewood.exe`는 `-server`를 주어도 실제 전용 서버로 동작하지 않아 서버 실행 대상으로 사용하지 않습니다. 현재 서버 실행기는 항상 Editor-Cmd를 사용하고, 실행·종료와 재접속 검증은 소유한 프로세스만 대상으로 수행합니다.

### 검증 도구 없이 두 계정으로 접속하기

현재 에디터 모듈을 빌드한 뒤 서버를 한 번 실행합니다. 이 실행기는 API/DB가 준비돼 있으면 재사용하며, 기본 `127.0.0.1:7789`에 화면 없는 전용 서버를 엽니다. 서버는 플레이어를 조작하지 않습니다. 플레이어는 아래처럼 별도 게임 창 두 개로 접속합니다.

```powershell
.\Start-OnlineServer.cmd
.\Play-Online.cmd -Register -Username mage_player -InitialClass Mage
.\Play-Online.cmd -Register -Username archer_player -InitialClass Archer -WindowX 950
```

각 실행에서 비밀번호를 숨긴 입력으로 받습니다. 두 창에는 서로 다른 계정을 사용하세요. 다시 접속할 때는 `-Register`를 빼고 같은 계정 이름·비밀번호를 사용합니다. `-InitialClass`는 계정을 처음 만드는 경우에만 적용됩니다. 비밀번호와 세션 access token은 게임 명령줄이나 상태 파일에 넣지 않으며, 서버 입장 URL에는 180초(3분) 유효한 1회용 입장권만 전달합니다. `LogInit/LogNet/LogLoad` 로그를 꺼 입장권 URL 출력을 억제합니다. 이 실행기는 검증 하네스 플래그나 게임 권한 검증을 생략하는 인자를 사용하지 않습니다.

기존 `Play.cmd`는 오프라인 시작 화면을 그대로 엽니다. 온라인의 주소와 API는 `Play-Online.cmd -Address 127.0.0.1:7789 -BackendUrl http://127.0.0.1:5281`로 지정할 수 있습니다. 서버의 `-Port`를 바꿨다면 클라이언트 주소도 맞춰야 합니다. `Start-OnlineServer.cmd`는 현재 소스의 Editor-Cmd 서버만 실행합니다. 클라이언트는 기본 Editor 게임 창을 사용하며, `Play-Online.cmd -PackagedExecutable <내부 Fablewood.exe>` 또는 `-LatestPackaged`를 주면 패키지 게임 창을 엽니다. `-LatestPackaged`는 완료된 패키징 보고서의 실제 내부 실행 파일 하나를 선택합니다. 두 클라이언트는 동일한 패키지를 사용하고 Editor 서버와 호환되는 이번 중앙 저장 구현이 포함된 빌드여야 합니다.

현재 PC의 온라인 클라이언트는 확인된 DX11 호환 경로(`-d3d11`)를 사용합니다. Editor 게임 창과 Windows 패키지 창 모두 같은 실행별 인자를 적용하며, `t.IdleWhenNotForeground 0`으로 다른 창을 선택한 동안에도 게임 진행을 유지합니다. OS GPU 드라이버나 프로젝트의 기본 렌더러 설정은 바꾸지 않습니다. 첫 실행의 초기화 시간은 환경에 따라 달라지므로 180초 입장권 유효시간 안에 항상 접속된다고 보장하지 않습니다. 만료되면 같은 계정으로 실행기를 다시 실행해 새 입장권을 받습니다.

`Saved/OnlineSessions/`에는 서버·클라이언트 PID, 실행 파일, 시작 시각과 로그 경로만 남깁니다. 실행기는 서버 포트 충돌을 거절하고 동일 프로젝트·실행 파일·시작 시각으로 확인된 기존 서버만 재사용합니다. 수동 런처의 `listening`/`launched` 상태는 포트 개방·프로세스 시작을 뜻하며, 실제 접속·저장·재시작 검증 통과 기록과는 구분합니다. 현재 설정은 로컬 PC 협동용이며 별도 인터넷 공개 서버 설정은 포함하지 않습니다.

### 소스와 에셋을 옮길 때

소스 전용 구성에는 `Source`, `Config`, `Tools`, `Backend` 코드·SQL·프로젝트·의존성 기록, 루트 실행기와 README뿐 아니라 실행에 필요한 `Content`의 `.uasset/.umap`, `ArtSource` 원본과 폰트 라이선스도 포함합니다. 바이너리 형식의 에셋도 편집·실행 입력이므로 실행 결과물과 구분합니다. 현재 필수 에셋 정적 감사는 68개 OBJ 원본과 대응 메쉬, 재질·맵·텍스처·폰트·음원을 확인합니다. `Build/Windows`의 아이콘 같은 원본 리소스는 포함하고, 출력 디렉터리 `Builds/`는 제외합니다.

`Binaries`, `Intermediate`, `DerivedDataCache`, `Saved`, `Builds`, `.vs`, 루트의 Unreal 생성 솔루션, `ArtDirection/Previews`, Backend의 `bin/obj/TestResults/artifacts`, DB 데이터와 실제 비밀 설정은 제외합니다. 기존 파일을 삭제하는 규칙은 아닙니다. `ArtSource/Meshes/*.obj`는 메쉬 원본이므로 `*.obj` 전체를 무시하지 않습니다. Backend에서 직접 작성한 `.sln/.slnx`는 포함할 수 있습니다.

```powershell

```

이 도구는 실제 포함 파일의 상대 경로·크기·SHA-256을 `Saved/SourceManifest/`에 기록하고, 필수 에셋·Source 파일 누락과 알려진 실제 비밀 값의 유출을 검사합니다. Git 초기화·스테이징·커밋·브랜치 작업은 하지 않습니다. manifest가 준비됐다는 결과는 빌드나 플레이 검증 통과를 의미하지 않습니다.

클린 작업본에서는 UE 5.8.4, MSVC 14.50, Windows SDK 26100을 준비하고 `Setup-Project.cmd`로 모듈을 빌드하고 포함된 맵을 확인합니다. 현 Setup은 전체 아트를 재생성하는 도구가 아닙니다. `Tools/Build-Art.ps1`은 메쉬·재질 재생성용이며, 폰트·음원·최종 조명에는 `Tools/Art/`의 개별 임포트 스크립트도 필요합니다. 기본 재현 경로에서는 포함된 에셋을 사용해 기존 맵과 아트 수정을 보존합니다.

과거 완료 보고서·개인 저장·이미지는 로컬 기록으로 그대로 보존하지만 소스 전용 구성에는 포함하지 않습니다. 특히 Talents·Loot·Workshop의 마이그레이션 회귀는 실제 과거 summary와 역할별 `.sav` fixture가 필요합니다. 별도로 보존한 원본을 `-SourceSummary`로 지정하고 SHA를 대조해야 하며, 새 체크아웃만으로 과거 회귀가 모두 재현된다고 간주하지 않습니다. 새 게임 검증과 역사 fixture 회귀를 구분합니다.

## 모험 순서

1. 로완에게 E로 말을 걸고 **2차 전직 시험**과 **숲 순찰**을 각각 선택해 수락합니다. 계열은 로완 근처에서 1·2·3으로 바꿀 수 있습니다.

3. 로완에게 숲 보상을 받고 숲의 무기를 장착합니다. 2차 시험 조건을 모두 채웠다면 보고하여 L을 해금합니다. K 적중이 부족하면 뿌리 유적에서 계속 채울 수 있습니다.
4. 두 플레이어가 **뿌리 유적의 심장**을 수락합니다. 마을 동쪽 포털에서 E → 뿌리 유적과 난이도 선택 → E로 입장합니다. 두 무리와 고대 수호자를 공략합니다.
5. 귀환 포털에서 E로 마을로 돌아와 로완에게 뿌리 유적 보상을 받습니다. 2차 전직을 마친 뒤 **3차 전직 시험**을 수락하고, **달빛 수원의 봉인**도 받습니다.

**3차 시험:** 2차 전직 후 수락합니다. 해당 계열의 L을 서로 다른 세 시전으로 실제 적중시킵니다. 마법사는 살아 있는 적에 둔화가 실제 적용되어야 합니다. 레벨 4 이상·뿌리 유적 보상 1회·달빛 수원 보상 1회를 함께 채운 뒤 보고합니다. 궁수 시험은 관통사격의 실제 적중을 요구하며 한 발의 다중 표적 적중을 필수로 요구하지 않습니다.

시험을 받기 전 쏜 투사체, 직업 변경 전에 쏜 뒤늦은 투사체, 빗나감, 같은 시전의 중복 적중은 시험을 진행시키지 않습니다. 판정은 서버의 실제 피해·둔화 결과를 사용합니다. 보상은 한 번만 지급하며 기존 저장의 전직 면제와 실제 시험 수행을 구분합니다.

## 저장

저장 형식은 **v6**입니다. 기존 레벨·재화·장비·물약·의뢰·전직·스킬·시험·지역 완료 이력과 장비의 품질·기준 성능·생성 비율·추가 옵션·세트를 유지합니다. 여기에 정수·뿌리 핵·달빛 결정, 개인 창고 장비, 장비별 현재/최대 내구도와 내구도 출처 버전을 저장합니다. 장비를 다시 불러와도 새로 굴리지 않습니다.

v1~v5는 원래 진행을 유지하며 v6로 전환합니다. v1~v4 장비는 기존 기본 수치·강화를 유지하는 고정 장비로, v5의 무작위 장비는 기존 품질·생성 비율·옵션·세트까지 그대로 보존합니다. **이전 저장의 장비는 모두 내구도 100/100으로 시작**하며 새 등급별 최대치로 바꾸지 않습니다. 새 공방 재료는 0, 개인 창고는 빈 상태로 시작합니다. 과거 장비에 옵션·세트·재료를 소급 지급하지 않습니다.

버전 속성이 생략된 과거 저장도 정규화합니다. v1의 초기 물약 3/2 처리와 v2 이후의 기존 물약 수량 보존, v1~v3의 기존 전직 시험 면제와 v4 이후의 실제 시험 진행 보존을 유지합니다. 지원하지 않거나 손상된 저장은 로드를 차단하고 원본을 덮어쓰지 않습니다. v5의 변환·재시작 완료 결과는 위 장비 파밍 기록에 있으며, 이번 v6 변환·공방 재시작 검증은 아직 완료로 기록하지 않았습니다.

진행은 호스트 PC의 캠페인별 `_Host` / `_Guest` 슬롯에 저장됩니다. 역할 슬롯이며 개인 계정과 연결돼 있지 않습니다. 새 게임은 고유 캠페인을 만들고 이전 파일을 보존합니다. 이어하기는 최근 캠페인을 사용하며 과거 캠페인 선택 UI는 없습니다.

실행 중인 적·봉인·보스 체력·스킬 재사용 시간은 전투 상태입니다. 서버 세션에 재접속하면 진행 중인 지역 상태에 합류하지만 앱 전체를 다시 실행하면 마을에서 시작하고 던전 전투를 새로 진행합니다. 개인 의뢰와 시험 카운터는 유지합니다. 전멸 시 마을로 구조되며 의뢰를 유지합니다.
