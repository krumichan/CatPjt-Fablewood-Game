# 층간 안내 화면 연동 · 2026-10-26 / 階間案内の画面接続

## 한국어

이번 단계는 층간 논리 경로 기초의 조회 결과를 이야기·일반 목적지 안내와 미니맵에 연결한다. 기준은 별도 보존한 `Fablewood-TownRoutes-20261026` 소스 387개이며, 기존 파티 준비 취소 검증본과 기초 모듈 동결본은 수정하지 않는다.

### 목적지와 표시 좌표

`FFableTownNavigationGuide`는 실제 서비스 설명자·실제 목적지 좌표와 표시용 waypoint를 분리한다. 다른 층의 서비스로 가는 경로가 있으면 현재 층에 있는 첫 연결통로 입구를 안내한다. 실제 `Service.WorldLocation`과 앵커·서비스 식별자는 원래 카탈로그 값을 유지한다. 기존 `ResolveService`의 같은 층 검사도 그대로 남겨 NPC 표식과 서비스 상호작용을 다른 층으로 확장하지 않는다.

새 Guide 조회와 이야기·controller 안내 출력은 실패 또는 다른 종류의 목표로 전환할 때 이전 route 데이터를 비운다. 같은 층의 서비스 좌표·기존 기본 문구는 유지한다. 경로가 끊겼거나 일방통행의 반대 방향이면 이전 마을 좌표로 대체하지 않는다. 미준비 지형·잘못된 현재 위치·없는 서비스도 이유를 표시하고 표시 좌표를 반환하지 않는다.

### 선택 우선순위와 화면

이야기의 마을 서비스 목표와 선택 의뢰의 서비스 fallback만 새 Guide 조회를 사용한다. 구조 대기·쓰러진 동료·전투·클리어 귀환·private 원정의 선택 우선순위와 기존 좌표 변환은 유지한다. 마을의 waypoint는 world 좌표이며, 원정의 정본 좌표는 기존 경로로 한 번만 변환한다.

`GetStoryTarget`과 `GetNavigationTarget`의 선택적 Guide 출력은 실제로 선택한 목표와 함께 전달한다. HUD가 별도로 다른 퀘스트나 서비스를 재조회해 화살표와 층 정보를 다르게 선택하지 않도록 한다. 층간 안내에는 통로 입구와 다음 층·목적지 층·남은 연결통로 정보를 표시한다. 표준 `F0`, `F1`은 화면에서 `1층`, `2층`으로 표시하고, 알 수 없는 내부 ID는 사용자의 판단에 필요한 일반 문구로 대체한다.

미니맵의 목적지 표식은 기존 같은 층 필터를 통과한 waypoint에만 그린다. 실제 다른 층의 NPC·최종 목적지를 현재 지도 평면에 겹쳐 그리지 않는다. 서비스/NPC 표식은 기존 엄격한 같은 층 조회를 사용한다. 현재 위치가 층 밖의 연결 회랑 안이면 다음 점을 추측하지 않고 통로 이동 중이라는 설명을 표시한다. 통로 내부의 연속 안내는 후속 범위다.

### 검증과 남은 범위

이 단계는 화면의 표시 데이터와 연결 코드를 구현하는 작업이다. 자동 이동·층간 순간이동·geometry 로드·저장·서비스 이용·파티 입장 권한을 추가하지 않는다. 네 후보 마을의 `geometryReady=false`와 기존 에셋도 유지한다. 실제 계단·경사로의 충돌과 보행 가능성, 화면의 가독성은 맵과 실행 환경에서 별도로 확인해야 한다.

Native fixture는 같은 층 호환, 다층·회전 좌표와 입구/실제 목적지 분리, 경로 없음·일방통행·미준비·이전 출력 초기화, 이야기/controller의 같은 Guide 전달과 private 원정의 좌표 변환을 대상으로 준비한다. 기초 모듈의 이전 로컬 C++ 9개 사례·89개 조건 통과를 이번 HUD·스토리·Unreal 통과 결과로 대신하지 않는다. 실제 Unreal/UHT/Native·화면·2인 플레이 검증은 아직 실행하지 않았다.

실행 검증은 먼저 기존 파티 준비 취소 동결본, 다음 기초 모듈, 이후 이 화면 연동본 순서로 진행한다. 이후 부모에 반영할 때 `FablePlayerController.cpp`의 안내 함수 변경이 기존 취소 QA의 RPC 관찰 코드를 덮어쓰지 않도록 변경 범위를 대조해 병합한다. 실제 검증을 마친 뒤에만 날짜·기능 단위로 소스 전용 Git 게시를 위탁한다. 빌드·캐시·실행 파일·로그·화면 캡처·DB·일회성 인계 자료는 Git 대상에서 제외한다.

## 日本語

今回は階間の論理経路の照会結果を、物語・通常の目的地案内とミニマップへ接続する。基準は別途保存した`Fablewood-TownRoutes-20261026`の387ソースであり、既存のパーティー準備取消検証と経路基盤の固定コピーは変更しない。

### 目的地と表示座標

`FFableTownNavigationGuide`は実サービス記述子・実目的地と表示用waypointを分ける。別階のサービスへの経路があれば、現在の階の最初の接続通路入口を案内する。`Service.WorldLocation`とアンカー・サービス識別子は元のカタログ値を維持する。従来の`ResolveService`の同階検査も残し、NPCマーカーとサービス利用を別階へ拡張しない。

新Guide照会と物語・controllerの出力は失敗や他種の目標へ切り替わるときに以前のrouteを消す。同階のサービス座標と基本文言は保つ。接続がない場合や一方通行の逆向きでは旧村座標へ代替しない。未準備地形・不正な現在地・欠落サービスも理由を表示し、表示座標を返さない。

### 選択優先順位と画面

物語の村サービス目標と選択依頼のサービスfallbackだけを新Guideへ接続する。救助待ち・倒れた仲間・戦闘・クリア後の帰還・private遠征の優先順位と座標変換は維持する。村のwaypointはworld座標であり、遠征の正本座標は従来どおり一度だけ変換する。

`GetStoryTarget`と`GetNavigationTarget`の任意Guide出力は、実際に選んだ目標と一緒に渡す。HUDが別の依頼やサービスを再照会し、矢印と階情報の目標が食い違うことを防ぐ。階間案内には通路入口・次の階・目的階・残る接続通路を表示する。標準`F0`、`F1`は画面では`1층`、`2층`とし、未知の内部IDは利用者に必要な一般的な文言へ置き換える。

ミニマップの目標マーカーは従来の同階検査を通過したwaypointだけに描く。別階のNPC・最終目的地を現在の平面に重ねない。サービス/NPCマーカーには従来の厳格な同階照会を使う。階の外の接続回廊内では次の点を推測せず、通路を移動中という説明を表示する。通路内の連続案内は後続範囲である。

### 検証と残る範囲

この段階では表示データと接続コードを実装する。自動移動・階間teleport・geometryロード・保存・サービス利用・パーティー入場の権限は追加しない。四候補村の`geometryReady=false`と既存アセットも維持する。実階段・スロープの衝突と歩行可能性、画面の読みやすさは実マップと実行環境で別途確認する。

Native fixtureは同階互換、多階・回転座標と入口/実目的地の分離、接続なし・一方通行・未準備・古い出力の初期化、物語/controller間の同一Guide、private遠征の座標変換を対象とする。基盤の以前のローカルC++ 9ケース・89項目成功を、今回のHUD・物語・Unrealの成功として扱わない。実際のUnreal/UHT/Native・画面・二人プレイ検証は未実行である。

実検証は既存のパーティー準備取消固定コピー、経路基盤、その後この画面接続の順で行う。後続の親へ反映するときは、`FablePlayerController.cpp`の案内関数変更が取消QAのRPC観察を上書きしないよう範囲を照合して統合する。実検証後に日付・機能単位のsource-only Git公開を委託する。build・cache・実行ファイル・log・capture・DB・一時引継ぎ資料はGit対象外とする。
