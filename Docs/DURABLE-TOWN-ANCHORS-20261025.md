# 안전 귀환지 V10 / 安全帰還先 V10

개발일 / 開発日: 2026-10-25  
문서 번역 보완일 / 文書翻訳補完日: 2026-10-26

## 한국어

캐릭터의 안전 귀환지를 TownId·AnchorId·CatalogVersion으로 저장한다. 위치 좌표, 원정 UUID, 접속 nonce와 이동 증서는 영구 저장하지 않는다. 네 후보 마을의 지형은 여전히 미채택 상태이며 새 캐릭터와 구형 프로필의 기본값은 LegacyVillage.Entry/catalog1이다.

원본 bytes/hash와 원래 버전의 wallet·inventory·summary를 먼저 검증하고 별도 후보를 V10으로 이전한다. UUID 도입 경계는 9, inventory/summary/index wire는 1로 유지한다. 유효 V9의 기존 필드·아이템 순서·UUID·옵션·내구도·절대 물약 UTC를 보존한다. 로드한 원본 V9와 후보에서 새 참조 세 필드와 버전만 제외한 V9 역투영을 동일한 현재 serializer로 비교하며, 기존 저장 필드가 하나라도 다르면 DB 이전 쓰기 전에 차단한다. 원본 raw bytes/hash는 별도로 그대로 보존한다. 엔진 changelist/custom-version 헤더 차이는 기존 게임 필드 변경으로 취급하지 않으며, 현재 엔진이 로드할 수 없는 과거 포맷까지 호환된다고 주장하지 않는다. 유효한 기존 10은 새 기본 정책으로 덮어쓰지 않는다.

정확한 V9/inventory1/명시적 summary:null만 원본 bytes 그대로 요약 확인 저장을 수행한다. 실제 ACK와 lease 반환 이후 새 ticket/claim으로 재접속하고 그때 V10 이전을 시작한다. 누락·잘못된 mirror·현재 10의 null은 보정하지 않는다. 일반 저장 대기열은 10만 기록하며 Backend DTO/SQL은 변경하지 않는다.

실제 이동 receipt에 대응하는 snapshot hash·소유 연결·이동/앵커 순번을 전송 전에 등록한다. 정확한 Sent ACK 또는 이미 확인된 동일 bytes와 실제 소유자 도착이 모두 확인돼야 source 지형과 입력을 해제한다. 이미 공개된 이동이나 결과가 불확실한 DB 저장을 과거 데이터로 되돌리지 않는다. 실제 도착은 원래 5초 안에 세 표본으로 확인하고, 도착을 유지하는 동안에는 저장 ACK가 5초 넘게 늦어도 같은 증서를 기다린다. 도착을 잃으면 원래 물리 기한을 다시 검사하며 저장 ACK만으로 입력을 풀지 않는다.

로그인은 실제 기존 원정 증서를 우선하며 저장 귀환지는 서버 전용 복원 경로로 지형·유한 slot·실제 capsule/floor·클라이언트 도착을 확인한다. 알려진 미준비 마을은 저장 참조를 보존하고 복원을 보류한다. 접속 전 schema10/catalog1/protocol1의 정확한 단일 옵션을 검사한다.

로컬 파일은 최초 이전 전에 원본 해시 이름의 backup을 쓰고 다시 읽어 확인한다. 현재 10 기록도 raw readback을 확인한다. SaveDataToSlot의 crash atomicity는 보장하지 않는다. 실패한 현재 파일을 새 캐릭터로 덮어쓰지 않으며 기존 continue index 형식 1을 유지한다.

### 검증 범위

Native의 memory/독립 slot fixture는 실제 DB 이전이나 플레이 이력이 있는 V9의 이전을 증명하지 않는다. 기존 582개 조건을 유지한 신규 빌드·실제 2클라이언트·저장/재로그인 감사와, 실제 이전 V9 데이터를 쓰는 별도 증거를 구분한다. 실행 전에 PASS로 기록하지 않는다. 신규 맵·외부 네트워크·Linux·게임 서버 재시작 후 결과 원장 영속화는 미검증이다.

## 日本語

キャラクターの安全帰還先を TownId・AnchorId・CatalogVersion として保存する。位置座標、遠征 UUID、接続 nonce と移動証票は永続保存しない。四つの候補の町の地形は引き続き未採用であり、新規キャラクターと旧プロファイルの既定値は LegacyVillage.Entry/catalog1 とする。

原本の bytes/hash と元のバージョンの wallet・inventory・summary を先に検証し、別の候補を V10 へ移行する。UUID 導入境界は 9、inventory/summary/index の wire は 1 を維持する。有効な V9 の既存フィールド・アイテム順序・UUID・オプション・耐久度・ポーションの絶対 UTC を保持する。ロードした原本 V9 と、候補から新しい参照三フィールドおよびバージョンだけを除いて V9 へ逆投影したものを、同一の現行 serializer で比較する。既存の保存フィールドが一つでも異なる場合は、DB への移行書き込み前に拒否する。原本の raw bytes/hash は別にそのまま保持する。エンジンの changelist/custom-version ヘッダーの差は既存ゲームフィールドの変更として扱わず、現行エンジンでロードできない過去の形式まで互換であるとは主張しない。有効な既存 V10 を新しい既定ポリシーで上書きしない。

正確な V9/inventory1/明示的な summary:null の場合だけ、原本の bytes をそのまま使って要約確認保存を行う。実際の ACK と lease 返却後、新しい ticket/claim で再接続し、その時点で V10 への移行を開始する。欠落、不正な mirror、現行 V10 の null は補正しない。通常の保存キューは V10 だけを書き込み、Backend DTO/SQL は変更しない。

実際の移動 receipt に対応する snapshot hash・所有接続・移動/アンカー連番を送信前に登録する。正確な Sent ACK、または既に確認された同一 bytes と、実際の所有者の到着の両方を確認してから、移動元の地形と入力を解放する。既に公開した移動や、結果が不確かな DB 保存を過去のデータへ戻さない。実際の到着は元の 5 秒以内に三標本で確認し、到着を維持している間は保存 ACK が 5 秒を超えて遅れても同じ証票を待つ。到着を失った場合は元の物理的な期限を再検査し、保存 ACK だけで入力を解放しない。

ログインでは実際の既存遠征証票を優先し、保存済み帰還先はサーバー専用の復元経路で地形・有限の slot・実際の capsule/floor・クライアント到着を確認する。既知の未準備の町では保存参照を保持して復元を保留する。接続前に schema10/catalog1/protocol1 の正確な単一オプションを検査する。

ローカルファイルは初回移行前に原本のハッシュを名前に使った backup を書き込み、再読込して確認する。現行 V10 の記録も raw readback を確認する。SaveDataToSlot の crash atomicity は保証しない。失敗した現行ファイルを新規キャラクターで上書きせず、既存の continue index 形式 1 を維持する。

### 検証範囲

Native の memory/独立 slot fixture は、実際の DB 移行やプレイ履歴のある V9 の移行を証明しない。既存 582 条件を維持した新規ビルド・実 2 クライアント・保存/再ログイン監査と、実際の旧 V9 データを使う別の証拠を区別する。実行前に PASS とは記録しない。新マップ・外部ネットワーク・Linux・ゲームサーバー再起動後の結果台帳永続化は未検証である。
